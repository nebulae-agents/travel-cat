# 公开源码边界

GitHub 仓库和源码 ZIP 只包含代码、公开工程配置、正式资源与测试夹具。本机部署配置、旅行数据、凭据、构建产物和部署备份不属于公开源码。

## 提交与发布检查

在提交或发布前运行：

```sh
python3 Scripts/github_preflight.py
Scripts/audit-project-upload.sh
```

检查覆盖整个 Git 索引，而不只检查本次修改。因此 `.local/` 中的配置、备份和部署记录，即使被强制暂存或已经跟踪，也会被拒绝。检查不删除这些文件，也不输出检测到的凭据内容。

`.gitignore` 是便利措施，不是完整的隐私保证。检查能够识别禁止路径、凭据容器和部分高置信度凭据格式，但不能证明任意文本都不含私人信息；提交者仍需查看完整差异。不要通过修改检查规则来发布自己的本地配置。

`config/deploy.demo.json` 仅提供使用 `~/` 的公开示例；实际配置只能由本地引导生成并保存在 `.local/deploy.json`。不要把个人绝对路径或额外字段填入 demo。

## 原始大资源的窄例外

普通文件仍使用默认 **5 MiB** 上限，不为初始化仓库全局放宽限制。三个现有 LXGW WenKai Lite 字体超过此上限，作为已存在的正式界面资源，按 [public-assets.json](../config/public-assets.json) 中的精确路径、字节数和 SHA-256 审核。

只有与清单完全一致的原始资源能够使用例外；资源变更、缺失或摘要不符都会阻止检查通过。清单不是任意大文件的通行证。更换或优化素材需要独立验收，并重新说明变更理由。现有字体及其相邻 SIL Open Font License 文件保留原样。

原始 `OFL.txt` 第 22 行带有行尾空白，首次完整导入的差异检查会提示这一既有格式。为保持第三方许可原始字节，不对它做格式化；此说明不豁免其他源码的空白检查或上传审计。

## 源码归档

`Scripts/export-source.py` 在干净 Git 提交上执行同一上传预检，并按公开文件清单导出；新增 GitHub 工程文件、部署入口、配置 schema 与 demo 可以进入归档，实际 `.local/` 文件不能进入。

正式 `Assets`、`Fixtures`、`Tests/Fixtures` 和 `Sources/TravelUI/Resources` 下的 `.log`、`.out`、`.err` 可能是资源或夹具，不能仅按后缀清理。`dist` 是可重建的临时打包输出，安装验证后应移除本次已确认的输出；旅行数据和部署备份必须保留。

这套检查不代表已经上传 GitHub 或通过 Apple 公证。项目代码、文档和自有素材的开源授权见根目录 LICENSE 与 NOTICE；第三方字体保留原许可。
