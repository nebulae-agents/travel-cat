# 本机私有部署配置

在仓库根目录运行 `python3 Scripts/configure-local.py`，按提示选择路径并确认摘要。这个入口只准备配置，不构建、安装、启动应用或生成旅行内容。

公开的 `config/deploy.demo.json` 只提供建议，不能代替个人配置。实际配置保存在被 Git 忽略的 `.local/deploy.json`，新配置只有以下三个字段：

| 字段 | 含义与建议 |
| --- | --- |
| `schemaVersion` | 整数 `2` |
| `applicationDirectory` | 应用安装父目录，只允许当前用户的 `~/Applications` 或 `/Applications` |
| `dataRoot` | 旅行相册目录，建议 `~/Library/Application Support/TravelCat/TravelPetData` |

首次使用时，只输入应用目录和相册目录，核对展开后的摘要，再输入“确认”或 `yes` 保存。空白采用建议；输入“取消”或 `cancel`、结束输入或按 Ctrl-C 取消。其他最终确认输入也会取消。输入错误会停止，不创建有效配置。旧 v1 配置仍支持原有四字段（额外包含 `codexHome`），复用不改写；选择重新生成时才转成 v2，原始字节保存在唯一备份中。新 v2 配置不允许携带 `codexHome` 或其他未知字段。

已有配置时，每次交互提供 `1` 直接使用（默认）、`2` 重新生成、`3` 取消。直接使用会重新校验，但不会改写文件字节、权限或 inode。重新生成默认保留旧路径，确认后生成唯一的 `deploy.json.backup-*` 备份，再原子替换。备份保存旧文件的原始字节，不覆盖先前备份。取消或提交前写入错误保留旧配置；提示期间有人修改配置或替换目录，也会停止。

损坏、未知或重复字段、超过 64 KiB、非普通文件、不安全权限或符号链接配置会被拒绝，不自动重建，也不会回退到 demo。若配置权限不符合要求，请先检查文件来源，再手动修复；向导不会为复用悄悄修改权限。`.local` 必须为当前用户所有且权限 `0700`，配置和备份为 `0600`。

非交互运行必须显式使用 `python3 Scripts/configure-local.py --reuse-existing`，并已存在有效配置；否则失败。交互中的同名参数不会绕过配置选择菜单。取消是正常停止，命令行返回 `0`；错误返回 `65`。调用部署模块时必须处理取消异常并停止部署，不能把取消当作有效配置。

路径只展开开头的 `~/`，不会展开环境变量、执行命令或读取 shell 配置。保存时使用绝对路径。代码仓库、两个可用应用目录、Codex 目录和旅行相册不能互相包含；重叠检查按目录组件进行 Unicode NFD 规范化并忽略大小写，也覆盖尚未创建的末尾路径。为兼容 macOS 常见文件系统，即使在区分大小写的卷上，也不允许仅凭根路径大小写或等价组合字符差异区分这些目录。路径不能以双斜杠 `//` 开头，不能含 `..` 或任意符号链接祖先。只接受系统原样存在的 `/tmp` → `/private/tmp` 和 `/var` → `/private/var` 别名。已有路径必须是目录；允许尚未创建的安全末尾路径。向导不会创建应用、Codex 或相册目录。

可以选择旧项目仓库中的 `TravelPetData` 来继续使用现有相册，只要它位于当前维护仓库之外并满足路径校验。修改 `dataRoot` 会明确提示将打开另一相册；配置重建不会读取、迁移或删除相册内容。部署调用方可以验证现有安装后，将原相册路径作为首次引导的建议；最终选择仍由用户确认。

上述 Codex 路径的校验与隔离要求仅适用于旧 v1 配置。新 v2 配置只检查源码、应用目录和相册之间的隔离，不访问默认 Codex 目录。公开示例和 schema 描述当前 v2；发布检查也严格兼容原四字段 v1 示例，以便检查旧提交，不允许私人绝对路径或未知字段。

不支持 `/System/Volumes/Data` 及其子路径作为配置路径，包括大小写变体；这些 macOS 卷别名可能重新指向维护仓库，绕过普通路径的目录隔离。请填写对应的普通绝对路径。向导不会通过创建文件来检测卷或别名。

私有配置、备份和后续部署记录不能提交、导出或放进公开问题报告。`.gitignore` 和公开发布检查共同执行这个边界。

## 部署入口的 Python 接口

`Scripts/deploy_config.py` 只依赖 Python 3.9 标准库，提供：

- `validate_config(config, *, repository, home=None)`：校验精确字段、展开建议，返回绝对路径字典。
- `load_config(*, repository, home=None)`：限量读取 `.local/deploy.json` 并校验；没有配置时抛出 `ConfigError`。
- `write_config(config, *, repository, home=None)`：校验后受限写入，已有有效文件先唯一备份；不接受坏旧文件。
- `choose_config(*, repository, home=None, interactive=None, reuse_existing=False, input_fn=input, output_fn=print, suggested_data_root=None)`：完整选择向导，返回有效字典；取消抛出 `ConfigCancelled`，校验或写入失败抛出 `ConfigError`。`interactive=None` 检查标准输入是否为终端，`home=None` 使用 `Path.home()`。`suggested_data_root` 仅影响首次引导，必须由调用方核实后提供。

写入使用独占临时文件、文件 `fsync`、受限权限和目录描述符。替换前同步备份所在目录，复核目录身份与旧文件字节及身份，最终以原子替换作为提交点。这保证其他读取者只看见完整的新旧配置；不承诺断电后最后一次目录重命名一定持久化，也不提供多个同时写入向导之间的事务锁。请一次运行一个向导。

## 从已提交版本部署到本机

双击仓库根目录的 `Deploy Local.command`，或从任意当前目录运行这个文件。终端调用也可使用 `python3 Scripts/deploy_local.py`。每次交互都会先显示配置选择；非交互运行必须显式加上 `--reuse-existing`。取消配置正常返回 `0`，部署错误返回 `65`。需要 macOS、Python 3.9 或更新版本，以及 Git、Xcode 命令行工具、Swift 和系统签名、复制、启动工具。安装位置需要当前运行账户有写入权限；入口不会自动提权。

首次向导可以从已签名且标识为 `com.nebulae.travelcat` 的现有应用读取显式相册路径作为建议。它只读取安装元数据，不读取相册。已安装应用的显式相册路径与新配置不同时，交互部署还会要求确认切换；非交互模式会拒绝，保留旧安装。

部署要求工作区、暂存区和 HEAD 一致，没有未跟踪源文件，并通过完整上传审计。仓库中已有 `dist` 等被审计禁止的生成目录会阻止部署。请先审查并提交源码；入口不自动提交、清理仓库文件或上传 GitHub。

部署从该提交导出经过审查的源码，在本次专用的仓库外临时目录中构建。相册路径写入应用元数据，源码提交写入 `TravelCatSourceRevision`。最终签名只更新外层应用，并复核内置命令行工具的字节哈希和来源记录。应用标识、签名、提交、相册路径、默认宠物资源字节全部核对后才准备替换安装。

部署只安装 `applicationDirectory/Travel Cat.app`。默认黑猫资源在应用内校验，不运行外置宠物安装器。Codex 宠物缺失时不会创建，已有自定义内容、历史备份和符号链接宠物目录均不参与发布；当前选中的 Codex 宠物和插件保持不变。新 v2 配置不检查或依赖 Codex 目录；复用旧 v1 配置时仍保留其原路径安全校验。

使用 v2 配置读取旧 v1 安装收据时，必须找到与旧收据配置指纹完全匹配、应用目录一致的私有 v1 配置备份，才能核对旧宠物目标。备份限 64 KiB，必须为当前用户所有的 `0600` 普通文件且非链接；超过 256 份备份会要求人工核实。没有匹配备份时停止，不根据收据中的旧路径自行授予权限。即使匹配，旧收据的未完成恢复状态仍阻止部署。

仅应用参与发布。候选与被替换目录临时放在应用目标的同一文件系统中，使用排他重命名避免覆盖并发出现的目录；不承诺进程意外中断时自动恢复。持久备份和部署记录在私有 `.local/deployment-*` 目录及 `.local/deployment-receipt.json` 中；真实 macOS 复制保留资源分支、扩展属性和隔离属性。构建日志保存在本次私有备份目录中。已有有效记录（包括因相册配置变化失去绑定授权的记录）会按原始字节另存为本次备份中的 `previous-receipt.json`，权限为 `0600`；备份失败则不开始构建。

入口只优雅退出目标完整路径对应的应用进程，等待退出后才发布文件，并验证、启动该完整路径的应用。后续步骤失败会撤销已完成的发布；原来运行的应用会在确认已退出后尝试重新启动。恢复无法完成时保留备份和临时目录，记录 `recovery-failed`，停止继续部署。`prepared` 记录也可能表示进程意外中断，必须先核实并恢复；入口不会自动猜测中断时的状态。请保留相关目录，检查当前目标、备份内容和记录后再处理。

新部署记录为 `schemaVersion: 2`，只有应用目标，不含 `petDigest`、`petAction`、`petExtras` 或插件版本。`sourceRevision`、`appDigest` 描述本次候选，结合 `status` 和 `stages` 判断是否安装成功；失败记录不能当作当前安装版本证明。日志、记录和备份属于私有资料，不可提交或公开。成功完成验证后，只清理经过身份核对的本次临时目录，持久备份继续保留。

v2 的 `complete` 记录必须精确包含 `prepared → app-published → verified → launched`，且 `error` 为空、`recoveryErrors` 为空列表；仅写一个成功状态不能获得覆盖授权。失败尝试另存于本次 `.local/deployment-*/receipt.json`。只有应用和原运行状态均成功恢复，恢复后的哈希也匹配上一份绑定当前配置的 v2 成功记录，才恢复该成功记录，以支持安全重试。旧 v1 收据仍按原精确字段、目标和宠物步骤顺序校验；迁移失败不会恢复其未经本轮验证的宠物管理授权，而是保留 v2 失败记录及旧记录备份。配置变更后已失效的旧授权不会恢复。任何部署记录写入失败或恢复失败都会保留阻断标记和相关目录，需要先人工核实。

只改变相册配置且目标路径不变时，经过完整校验的旧部署记录不再提供恢复成功记录的授权，但仍检查其恢复阻断状态。更改应用目标路径会因旧记录的目标绑定不符而停止；旧 v1 收据还要求原 Codex 目标绑定一致。必须先审查原安装和记录，不能靠篡改记录获取授权。损坏记录、未知字段、非普通文件、错误权限、符号链接或未完成恢复的记录始终被拒绝。

该入口不会生成旅行内容、更新自动化、切换宠物、刷新 Codex 插件或编辑插件缓存，也不读取插件源码版本。流程不会移除隔离属性或修改系统安全设置。事务和配置迁移经隔离测试验证，真实本机安装验收仍需后续完成。
