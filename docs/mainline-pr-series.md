# 主干合并准备：四个顺序 PR

按 2026-10-14 用户要求，每步分别修复、验证并提交 PR，不自动合并主干。现有 PR #2 保留为依赖。

1. 图片修订索引：导出、清历史备份、成功清理与失败回滚；保留旧根兼容及链接拒绝。
2. 版本候选：移植双面明信片和生成改进，以及未读优先、图片身份性能、历史提示快照；保留公共角色和便携安装能力。
3. 交互验收：卡面点击、翻面状态及旧回调保护、隔离恢复夹具；实际检查翻面与配置取消/恢复/一次失败重试。
4. 最终验证：完整 Swift 与工程契约回归，当前提交对应的远端 CI，当前行为与合并门槛记录。

通过公开预检与上传审计后提交明确文件清单。源码移植采用逐文件三方合并，保留公共历史和已有能力。正式旅行数据、私人收件信息、无关照片与构建包不进入公开提交。测试、安装、客户端和远端证据分别记录；客户端证据未完成时 PR 保持草稿。
