## 2026-11-22 桌面接管写入的可行性验证

在 `ed7d2e3` 的临时数据根上，用独立 Swift 进程打开根目录本身，并使用与 [Python 服务](../Runtime/agentxd.py)相同的非阻塞排他锁。Swift 持锁时，第二个 Swift 进程和实际 Python 服务均被拒绝，服务未发布端点。Swift 释放后，Python 能接管并发布端点，此时 Swift 被拒绝。Python 退出后，Swift 能再次接管。

这项结果只覆盖进程间互斥和双向交接。桌面已有的[单实例锁](../Sources/TravelCatApp/SingleInstancePolicy.swift)锁定的是单独文件。下一步要把根目录锁接入实际 App，在开放接口前取得锁，随后验证列表、创建和退出回收。HTTP 与 WebSocket 的实现方式仍待选型，可用上述相同请求对照系统网络框架与现成服务库的行为、依赖和打包成本。

## 普通桌面运行中强制退出与恢复

2026-11-22，基线 `ed7d2e3` 加本地改动。在原有普通桌面验收脚本中加入 `--interrupt`。脚本使用临时 App、临时数据根、本轮 Pi runner、已安装包内的 Node 与依赖，以及本机模拟模型。等模型收到请求、桌面读到“运行中”后，脚本向自己启动的 App 发送 SIGKILL。修复前，桌面重启后仍显示运行中，旧 Pi 超过 20 秒仍存活。

| 核对项 | 修复后实测 |
| --- | --- |
| 子进程 | 测试从运行凭据取得旧 Pi PID，在重启桌面之前的 5 秒观察窗口内确认该 PID 已消失。旧 App 没有写下回收确认，原凭据仍为 `reaped=false`。 |
| 运行与重试 | 重开的桌面读到原运行 ID，状态为 `failed`、`unverified`、待核对。同键同内容返回 200 和原记录，同键改内容返回 409；该实例在待核对期间收到不同请求键也返回 409。模型只收到一次请求，只有一份 Pi 进程凭据。 |
| 审计恢复 | 第一次恢复时故意提供错误的临时审计密钥。运行先落盘为中断，修订号加一，留有待补审计标记。用正确密钥重开后补写终态，清除标记，修订号再加一。第四次启动重试后，运行文件和两条加密审计记录均逐字节一致。原有历史文件也保持一致。 |

正常退出的双启动场景同时复验通过。定向 XCTest 33 项、Swift Testing 9 项、Pi runner 6 项和 Python Runtime 289 项全部通过。XCTest 单独核对了恢复时缺少开始审计不会创建新密钥，以及已有终态审计会被保留。

复验命令为 `python3 -B Scripts/run-agentx-desktop-writer-acceptance.py <含-Pi-运行时的应用包> --interrupt`，先按上一节构建调试版。此次覆盖单应用在请求执行中遭遇进程强制退出；多应用及其余 API 契约仍待验证。正式客户端和正式数据未参与本次验收。[隔离验收脚本](../Scripts/run-agentx-desktop-writer-acceptance.py)

## 普通桌面 HTTP 事件补读

2026-11-23，在 `ed7d2e3` 加本地改动的普通桌面调试包和 Python 参考服务上，分别用临时数据根启动两个登记应用。验收调用 `GET /v1/apps/{appId}/runs/{runId}/events?after=N`，其中 N 是客户端最后收到的修订号。改动前，同一份无事件的旧记录在 Python 返回版本 0 和空列表，桌面返回 404。补齐桌面路由和运行事件后，两端通过了同一组请求。
