# 可移植运行环境

本文描述通用发布改造目标及兼容边界。完整发行状态以测试报告为准，不以本文替代验收。

## 新用户

默认发布包不包含作者个人目录。应用与随包的签名 CLI 使用当前用户的 `Library/Application Support/TravelCat/TravelPetData`。这份数据包含旅行记录，不应随源码提交或分发。

插件必须调用随应用提供的 `Contents/Resources/run-travelcatctl`，不可调用开发构建，也不需要用户填写模型或 API Key。旅行生成使用 Codex 的能力，仍受用户额度、权限和运行条件限制。

## 已有安装的兼容

如果旧应用通过 Info.plist 的 TravelCatDataRoot 使用非默认数据目录，新包必须显式保留这个目录后再替换旧应用。普通发布包不会自动搜索或迁移旧数据。

兼容打包形式：

```sh
Scripts/package-app.sh --data-root /absolute/existing/data-directory
```

此参数只将目录写入新包配置，不复制或修改该目录。包含个人目录的兼容包不可作为公共发行包；公开包使用无参数打包。安装前应核对新旧数据位置，不要用空相册来判断旧数据已丢失。

## 安全与发行限制

CLI 在执行固定命令前校验应用签名与辅助程序摘要。不要通过修改已签名应用内文件配置目录，修改会破坏签名；应重新打包。

当前打包脚本使用本机临时签名，不等于 Developer ID 签名或 Apple 公证。对外二进制发布必须单独验收系统首次启动提示，不能要求用户关闭系统安全保护。

本次开发不替换现有安装，不迁移真实相册，不创建或替换生产旅行自动化。
