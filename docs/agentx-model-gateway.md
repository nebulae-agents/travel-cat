# AgentX 模型网关配置与首段验收

2026-11-25，M3 / OPT-03、OPT-07 的实现契约。配置读取、桌面托管回环网关、共享日预算及 Controller 普通对话/工作流接入已通过本机隔离验证；真实上游、预算管理界面与正式安装仍待验收。

## 配置

数据根的 `manager/gateway.yaml` 使用以下版本 1 结构。示例中的应用、服务和模型 ID 需引用同一数据根的已有配置。

```yaml
version: 1
applications:
  alpha:
    provider: local
    model: fixture
    max_output_tokens: 1024
    max_request_bytes: 1048576
    timeout_seconds: 65
```

配置只引用已有 provider。地址和凭据通过现有 provider 配置、凭据配置档和系统钥匙串解析。字段中的整数必须为正值，拒绝布尔值、浮点数、重复键、未知字段和未知版本。首段上限分别为 65536 个输出 token、1048576 字节和 300 秒。超出模型自身限制时采用更小上限。应用、服务和模型必须存在且启用，应用成员的模型绑定必须匹配。文件缺失时，真实上游网关入口不可用。

这些数值是首段实现采用的可调整边界，需要随实现通过边界测试。最大输出 token 是单次调用上限，费用预算还需要独立的价格、币种和日预算规则。

## 请求与密钥

桌面在取得数据根独占锁后创建回环监听，端口由系统分配。每个运行使用独立的随机凭据，绑定数据根、应用、运行、provider 和 model。凭据仅允许该运行的一次上游提交，结束、取消或过期后失效。请求不得自行覆盖目标 URL、模型、身份或额外请求头。鉴权失败时返回通用错误。

Pi 通过 stdin 接收回环地址和临时凭据。桌面临提交时解析上游密钥，仅在请求受控上游时添加 Authorization。密钥不写入事件、运行文件、命令行、环境变量或响应。审计开始失败时，上游请求次数必须为零。取消要中止上游并等待 Pi 退出，按既有运行凭据确认回收。

客户端重复提交原运行键时返回已有运行。网络失败或丢失响应时，首段不自动重新发送可能已经被上游接受的请求。重启后的未完成运行按现有中断恢复规则处理。

## 流式、用量与预算

首段接入 OpenAI-compatible 的 chat completions 流式响应。网关校验请求体大小和输出上限，传递可见文本增量。上游错误响应使用通用错误码，保留已收到的文本。流式解析覆盖分块 UTF-8、空 choices 的用量帧、异常结束和取消。

每次调用记录 provider、model 和上游实际报告的输入、输出 token。缺少用量时标记 unknown。费用记录需要币种、价格来源及版本，缺少价格时费用同样为 unknown。禁止将缺失值填成零。

费用预算启用后，提交前必须完成持久化额度预留。并发请求共享同一预算账本，超额或无法确定预留金额时拒绝调用。结束后以可信用量结算，缺失用量时保留待结算预留。跨日以配置的时区和请求预留时的预算日处理，取消和重启均不能重复释放额度。价格格式和日预算配置将在 OPT-07 实现时补齐，费用预算尚未可用时界面继续标注其状态。

## 隔离验收条件

1. 使用两个临时应用和本机受控上游，采用测试凭据。上游断言收到正确 Authorization，Pi stdin 捕获断言不含上游凭据。
2. 错应用、错模型、过期、复用和撤销凭据全部拒绝，上游调用次数为零。
3. 首段文字在终态前抵达事件订阅和窗口。上游报告用量时如实保存，省略用量时保存 unknown。
4. 请求过大、输出限额、超时、审计不可用和手动取消均得到可解释终态。重试同一运行保持一次上游提交。
5. 两应用并发、一次中断及重启恢复后核对运行、事件、审计和子进程退出凭据。
6. 费用预算实现后补测并发预留、超额拒绝、缺失价格、缺失用量、取消和跨日恢复。

首段先完成本机受控上游闭环。真实服务调用涉及正式凭据和费用，按里程碑单独授权并记录结果。

## 托管网关日预算隔离验收（2026-11-25）

同一数据根的托管应用共用 `manager/gateway-budget.yaml`。这是可选的本地预算配置；以下金额仅用于测试，不是市场价格或正式预算：

```yaml
version: 1
currency: USD
time_zone: Asia/Shanghai
daily_limit: "0.2"
prices:
  local:
    fixture:
      input_per_token: "0.001"
      output_per_token: "0.002"
      source: "local fixture, not market price"
      revision: "v1"
```

金额必须为非负十进制字符串，最多 12 位小数；日限额须大于零，金额整数部分最多六位。内部用 10^-12 币种单位的整数计算并检查溢出，不经过浮点数。币种和时区在账本建立后不可直接替换；同币种的日限额可以显式调整。价格来源与版本由配置者填写，不自动验证远端价格，不作汇率换算。

提交前按模型目录声明的 `contextLength × 输入单价 + max_output_tokens × 输出单价` 持久预留。缺少价格或上下文上限、存在阶梯/非零附加计价、无法计算金额、账本不可写或额度不足时，不提交上游。该预留依赖提供商遵守声明的模型边界，不等同于控制其实际账单；超界用量或计算溢出会留下报告并阻止后续调用。

所有应用在同一桌面根锁下串行检查和写账本。`manager/gateway-budget-v1/ledger.json` 保存每个应用/运行的原预算日、价格快照和状态，文件及父目录均经 fsync。`manager/.gateway-budget-v1` 与根级 `.gateway-budget-required-v1` 记录启用身份；配置、账本或这些标记丢失/不匹配时失败关闭。当前进程还记住已经初始化，不能因文件消失恢复额度。跨重启恢复依赖这些持久状态；主动同时移除全部预算状态与根级启用标记不属于损坏恢复保证。

只有合法 stop、最终完整用量和 DONE 都被确认后才按该次价格快照结算差额。取消、断流、异常尾帧、缺失或不完整最终用量保留预留为 pending；已报告用量仍单独保留，不能冒充最终账单。跨日结算记回原预留日，不占用新一天的额度。相同运行不能重复预留，结算和取消回调均幂等。不确定的持久化写失败会阻断当前预算实例，重启后重新核对磁盘状态。

服务运行诊断包含启用预算的 `budget` 摘要；运行生命周期快照包含预算回执。`held` 是占用额度，`spent`/`actual` 是按配置价格和可信用量计算的已结算金额，不是服务商账单。`actual=null` 表示尚未确认，不能显示为零。请求可先进入 running，再因预算拒绝而进入 failed，失败原因明确说明预算；该过程不会产生上游模型调用。

`Scripts/run-agentx-gateway-budget-acceptance.py` 已在临时桌面和真实 Pi 上验证：甲运行时占用 0.146，乙被拒绝且无上游调用；取消甲和重启后仍保留该额度；显式提高测试日限额后乙完成，结算 0.017；正常 stop/用量后出现异常尾帧的另一调用保留 0.146，不释放差额。缺价格、删除预算配置或网关配置均不回退直连。三次实际调用各一次，结算与预留跨重启稳定。无预算的既有网关隔离验收也通过。

单元测试还覆盖精确金额、配置类型、跨日结算、币种/时区约束、金额溢出、只读目录写失败、账本及双标记丢失。独立复核发现的异常尾帧与重新初始化问题均已修复复验。

仍未覆盖：非托管 Controller/工作流入口、预算设置界面、真实供应商价格及账单校验、人工处理长期 pending 预留、正式安装和 GUI 交互验收。此次未设置正式预算，未读取真实模型密钥，未提交、推送或安装。


## Controller 对话与工作流接入（2026-11-25）

`AgentXHostGateway` 将普通对话、人物/配置辅助、使用助手和工作流步骤接入现有网关。启用 `gateway.yaml` 时按当前应用绑定执行；配置损坏、成员或模型不一致、仅存在预算配置/启用状态而网关缺失时均拒绝，不回退直连。当前应用网关仍只绑定一个模型，多模型工作流不在此配置支持范围内。

没有网关和预算状态时保留旧配置兼容；每次实际调用前仍重新检查是否新增网关/预算。工作流启动后开启网关或预算，后续缓存步骤会拒绝执行，用户需重新提交。不能追溯限制配置启用前已经发出的请求。网关调用则在解析密钥前再次核对应用、成员、提供商、模型及凭据引用。原有开始审计仍先于网关监听和模型提交。

Pi 只接收一次性回环地址及令牌，`secret` 为空；native-http 直接消费网关提供的受限 SSE，保持原运行时身份。取消会关闭网关和上游连接。Controller 与桌面 writer 共用同一预算对象和根锁；没有 writer 时，Controller 在首次合法网关运行前取得并保留独占根锁，不能与另一个 writer 同时使用该根。

工作流逐步预留和结算，预算账本键为每步的 `stepRun.id`；Pi 进程退出凭据仍使用外层工作流 run ID，确保停止检查覆盖流程。额度不足时当前步骤及流程失败，后续步骤不执行，记录说明预算原因。普通对话的账本键为其 run ID。当前详细预算回执保存在共享账本中，Controller 尚未增加预算展示或编辑界面。

自动化隔离验证覆盖：native-http 与 Pi 进程夹具均只调用本机网关；上游收到正确测试鉴权和 23 token 上限；每次调用结算 0.017。日限额 0.16 时两步流程只执行首步，第二步预留不足，未增加上游调用。取消保留 0.146，后续调用被拒绝；删除网关不恢复直连；其他应用占用共享额度也阻止 Controller 提交。以上仅为测试价格。

使用安装包中的 Pi 可执行文件和依赖、当前源码 runner，在临时目录运行两步 Controller 工作流：两次本机上游请求，各结算 0.017，合计 0.034；外层运行的进程退出凭据已确认。该验证通过 XCTest 驱动 Controller，不等同于 GUI 点击验收或安装新版。可通过 `AGENTX_TEST_PI_NODE`、`AGENTX_TEST_PI_RUNNER` 显式传入隔离运行器，执行 `Scripts/travel-cat-swift.sh test --filter AgentXHostGatewayTests`；未传时真实 Pi 专项明确跳过，其他测试继续运行。
